# hitSlop 1.2.0

## Mac app

### New

- Live collaboration is available from the Share menu. Sign in with Apple to create a link, then edit the same slop with others on Mac, iPhone through [TestFlight](https://testflight.apple.com/join/F4qfCkgg), or Chrome. Stop sharing at any time; everyone keeps their copy.
- Sign in with Apple on Mac through your browser, using the same sharing account as the iPhone app.

### Improved

- Sharing explains when a room or its attachments are full, an update is needed, or a link has ended, with an action to help you continue.
- Shared rooms make better use of their storage as you edit, and recover from temporary connection failures.
- A warning appears when a document is nearly full. Duplicate and Save Unshared Copy preserve your latest accepted edits even when a shared or library document can no longer save.
- New documents created from the bundled starters leave room for the iPhone editor's native actions and system edges. Existing documents keep their original app layout.

### Fixed

- Save Unshared Copy checks for text that could not be saved before leaving the original document. On Mac, copy that text, discard it, or cancel and keep editing.
- Undo continues past changes that a collaborator has already made irrelevant.
- Sharing shows an update prompt when a newer version is required, rather than a generic refusal.

## Authoring

- Phone editors expose `--slop-safe-top`, `--slop-safe-bottom`, `--slop-host-actions-width`, `--slop-host-actions-height`, and `--slop-keyboard-inset` to keep content clear of system edges, native actions, and the keyboard. The CLI starter and authoring guides describe how to use them.
- Focused text fields remain visible when switching device presets in `slop dev`, even without an on-screen keyboard.
- Attachment command help and guides clarify that shared and library documents retain unreferenced attachments for other copies. An unshared clean copy keeps only the attachments its current state references.

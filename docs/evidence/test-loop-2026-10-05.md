# Test loop, before and after (2026-10-05)

Measured on the M1 (8 cores) used for development, with other applications running (load
average between 6 and 44 during the runs), so single numbers are indicative. "Before" is
the tree at `d01497eb`; "after" is the testing pass that introduced `bun run verify`.

| Loop | Before | After |
|---|---|---|
| `bun run build`, nothing changed | 71.7 s: `hitslop-core` recompiled in five Cargo graphs, because contract generation rewrote `wire.generated.rs` and the schema files `build.rs` watches; Swift recompiled from `HitSlopCoreBinding` up | 6.7 s |
| Rust: first full run after a build | 12 min 36 s wall for 35 s of CPU: macOS checked each new test binary at first launch | 3 min 16 s cold from `cargo clean` (build 3 min 1 s, tests 13.6 s) |
| Rust: one-line core edit, then the suite | compile alone 7 min 1 s | 23.8 s (build 9.6 s, tests 13.5 s) |
| Rust: repeat, nothing changed | 32.2 s (`cargo test`, serial) | 13.6 s (nextest) |
| `target/` | 50 GB (debug 45 GB, 323k files in `deps/`) | debug 1.2 GB, release 0.9 GB |
| Static checks (`check`) | 8.5 s | 5.0 s (`hygiene`, `contracts`, `types` together) |
| Bun tests (`test`) | 59.4 s | 24.4 s (0.9 s no-op build; `bun test --parallel`; `build.test.ts`, 34 s alone, split in three) |
| Swift tests | 134 s (121 s with nothing to build) | 75 s (three process shards, about 50 s of tests) |
| Native tools (`test:native`, `test:render`, `test:compat`, `test:native-helper`, crash matrix) | 59.5 s as five commands | 51 s as one tier, including its 5.7 s no-op build (62 s once the corpus held its page-saved documents) |
| Everything but packaging and the app (`release:check`'s test stages, plus the Rust suite it lacked) | about 7 min of stages, plus 12.6 min for the Rust suite's first run | 214 s (`verify --all --native`, load average 13) |

What made the difference:

- Developer Tools for the terminal (`spctl developer-mode enable-terminal`): a fresh
  binary's first launch went from about 300 ms (seconds under load) to under 10 ms.
- One Cargo graph for every host build: uniffi without its default `cargo-metadata`
  (the generator is installed on its own), the WASM adapter's dependencies only on WASM,
  `storage` a default feature, and on a Mac the engine always built together with the app's
  core library (alone, uniffi's build dependencies change `serde`'s features and each build
  undid the other). Debug info for tests is line tables only, none for dependencies.
- Outputs written only when their bytes change: generated contracts, Swift bindings and
  headers, the static library and XCFramework, the WASM bindings and the page shell.
- nextest, one process per test on every core; the Swift suite in three processes balanced
  by recorded durations (five runs at three shards and two at four, under load, without a
  failure; four were no faster).
- `bun run verify` runs only the tiers whose inputs changed since they last passed.

Measured and not adopted:

- One integration binary for the Rust tests: after an edit the core library rebuilds in
  2.2 s and the 22 test crates recompile and link in parallel in about 7 s more, so merging
  them would save about 3 s, under the 5 s bar `plans/faster-test-loop.md` set.
- Incremental release builds of the WASM core: 4.0 s → 1.0 s after a core edit, but the
  release's WASM must stay byte-identical to its frozen capture.
- nextest priorities for the storage tests that wait on real SQLite busy timeouts: no
  measurable change; the run is bounded by its slowest test (8.6 s).
- mold: it links ELF only; the Mac builds use Apple's linker.

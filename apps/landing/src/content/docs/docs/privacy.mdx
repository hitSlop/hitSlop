## Documents, devices and speech

Recordings, photos and transcripts saved by a pop are document content and travel
with the `.pop` file when you send a copy. A pop must declare camera or microphone
access before the host admits a capture request. macOS permissions are granted to
pop as an application; there is no separate per-document permission dialog yet.
Change those decisions in System Settings → Privacy & Security.

The `speech.transcribe` service recognizes stored recordings on-device on the Mac.
If the requested language cannot be recognized locally, it reports that limitation;
it does not fall back to sending the recording to a server. Speech Recognition has its
own macOS permission, separate from Microphone. See
[capabilities and permissions](/docs/guides/capabilities/) for the exact limits.

Pop can make HTTPS requests and load external images, media and embedded web pages.
Those requests reach their respective providers. Local document storage and on-device
transcription do not mean that all authored apps work offline or never use the network.

## Cloud documents and collaboration

Cloud sync is optional. Local-only documents require no account or upload. To sync,
the owner signs in with Apple through Firebase Authentication. On Mac, sign-in opens
Apple's page in a browser sheet; iPhone uses Apple's native sign-in.

Enabling sync uploads the embedded app, document state and referenced attachments to
Cloudflare. Durable Objects and private R2 storage hold the current document and the
bounded replication data needed for synchronization. Account Durable Objects hold derived
library metadata such as document IDs, titles, app identity and access status. This
content is not end-to-end encrypted. Synchronization retains document history, including
content removed from view; routine checkpoints and compaction do not erase it. Live
collaborators can receive that retained content. **Share a Copy** sends an independent,
sanitized copy instead. Cloud storage does not provide a document history interface.

Sharing grants access to that same cloud document. Anyone with the invitation can edit;
anonymous guests need no account. Signed-in guests can discover joined documents on
other devices while their invitation remains active.

Stopping collaboration revokes guest access while your own devices keep syncing.
Cloud documents do not expire merely from inactivity. **Delete Everywhere** deletes
the cloud payloads and revokes access. Minimal service lifecycle records prevent delayed
requests restoring a deleted cloud document. A guest's library reference may remain
listed until their device checks access and cleans it up. Already downloaded participant
copies remain on their devices. **Delete Account** deletes owned cloud documents and
joined memberships before deleting Firebase identity, and attempts Apple access
revocation. Signing out alone hides the account library and pauses this device's sync;
it does not delete cloud documents or end links. See
[live sharing](/docs/guides/live-sharing/) for these controls.

Sharing event metrics record event names and counts, without document contents,
account or document identifiers, IP addresses, tokens or edit links. The service uses
client IP addresses to apply request limits and does not store them after a connection
closes.

## Analytics and crash reporting

Release builds of the Mac and iPhone apps enable Firebase Analytics and Crashlytics. They send
launch, open, create (source), duplicate and export (format) events; operation
breadcrumbs; failure records with fixed operation, classification, reason and format
fields; crash reports; and Firebase's standard app and device data.

Our custom event, breadcrumb and failure fields do not include document contents or
file paths. Automatic crash reports contain diagnostic information collected by the
Firebase SDK. Collection is enabled in release builds with no in-app toggle; Debug
builds and tests do not upload telemetry.

A slop is a focused app and its document in one portable `.slop` package. Start with a working Checklist, then make the interface and data your own.

## Install the tools

Use Bun 1.4.2 or newer, on macOS or Linux. Creating, previewing, checking and building an app, and creating or editing its documents, need only the CLI. To register templates, open windows, render Finder artwork and export PNG/PDF, install the matching hitSlop Mac app in `/Applications` or `~/Applications`. You do not need Node, Swift, Xcode, or a hitSlop repository checkout.

The public CLI workflow is:

```sh
bunx hitslop init tiny-counter
cd tiny-counter
bun install
bun run dev
```

After the setup questions, an example response is:

```text
Created /Users/you/tiny-counter. Run bun install in that directory, then bun run dev.
```

`cd` prints nothing on success. `bun install` prints an installation summary (counts
and timings vary). `bun run dev` starts a long-running preview and prints:

```text
Disposable preview: http://localhost:5173/
```

If port 5173 is busy, choose another with `bun run dev --port 5174`.
Stop the preview before continuing with builds.

Alternatively, install the CLI with `bun install -g hitslop` and run `slop init tiny-counter`. The generated project pins its own `hitslop` version; prefer its `bun run` scripts after creation.

See [CLI workflows](/docs/guides/cli-workflows/) for command entry points, document creation, editing, moving data between documents, export, and agent skill installation.

`init` asks you to describe your slop and who the author is. It starts from a working Checklist, saves your idea in `BRIEF.md`, and includes `AGENTS.md` and authoring/design skills in `.agents/skills/`.

The final question asks which agent CLI should build it for you. Choose an installed Codex, Claude Code, Gemini CLI, or OpenCode, or select **Other CLI…** to enter a tool such as Grok and its prompt option. The agent launches in your project with the brief and hitSlop guidance. Choose **Finish without launching** to follow the tutorial below yourself. Add `--yes` for a non-interactive starter; this never launches another agent.

## Understand the source

Read `slop.ts` first. It declares the app with `defineSlop`: its title, description, author, categories, initial window size, theme colors and optional artwork. Its explicit `slug` identifies the app. The wizard records your author name, and the agent sets the title, description, and categories to match what it builds; you can edit these and the initial window size anytime.

- `schema.ts` default-exports the document fields and creation-only initial values.
- `commands.ts` optionally default-exports agent commands; the starter includes `addTask`.
- `App.svelte` renders and edits the document through typed handles.
- `slop.ts`'s `theme` declares the colors people can change.
- `styles.css` owns layout and component styling; import it explicitly from `App.svelte`.

The root role filenames are fixed and case-sensitive: `slop.ts`, `schema.ts`, `App.svelte`, optional `Export.svelte`, `Icon.svelte`, `Widget.svelte` and `commands.ts`. Put helper modules anywhere. `Widget.svelte` supplies saved-state desktop images; see [widget authoring](/docs/guides/icons-and-exports/#design-a-macos-widget).

The browser preview edits a disposable copy of the document; refreshing starts a fresh one. Vite watches source changes. Component and CSS updates preserve accepted edits; a change to metadata, schema, commands, their dependencies or the role inventory resets the copy. Test native persistence in a writable document copy.

## Turn the starter into a counter

Replace the starter's data definition:

```ts title="schema.ts"
import { defineDocument, s } from "hitslop";
export default defineDocument({ title: s.text(), count: s.counter() }, { initial: { title: "Tiny Counter" } });
```

Then describe the counter in `slop.ts`. Its `theme` declares the colors `styles.css` uses below:

```ts title="slop.ts"
import { defineSlop } from "hitslop";

export default defineSlop({
  slug: "tiny-counter",
  title: "Tiny Counter",
  description: "Count the small things worth counting.",
  author: { name: "Your Name" },
  categories: ["utilities"],
  window: { kind: "standard", width: 360, height: 360, fullscreenable: true },
  theme: { surface: "#fff7e6", ink: "#382d24", accent: "#28634b" },
});
```

`fullscreenable: true` enables the native fullscreen control. This flexible window
fills the screen; fixed and shaped designs fit their composition on black.
See [fullscreen behavior](/docs/guides/manifest-and-windows/#enable-fullscreen).

Replace the starter's `commands.ts` with a counter action:

```ts title="commands.ts"
import { defineCommands } from "hitslop/commands";
import doc from "./schema";

export default defineCommands(doc, {
  countOne: {
    description: "Count one more.",
    args: {},
    run({ tx }) { tx.fields.count.increment(); },
  },
});
```

The CLI discovers `countOne` from this set. Commands are for agents; their arguments
are flat scalars or optional scalars, or `{}` when none are needed. The page below
edits with its document handle. To give the button and an agent one shared edit, see [share an edit with agents](/docs/guides/data-and-schemas/#share-an-edit-with-agents).

Replace `App.svelte` with:

```svelte title="App.svelte"
<script lang="ts">
  import { EditableText } from "hitslop/svelte";
  import doc from "./schema";
  import "./styles.css";
</script>
<main class="counter">
  <EditableText class="counter-title" field={doc.fields.title} label="Counter title" placeholder="Name it" />
  <p class="counter-value">{doc.current.count}</p>
  <button data-slop-export="hide" onclick={() => doc.fields.count.increment()}>
    Count one
  </button>
</main>
```

PNG and PDF exports render this view independently from the saved document; `data-slop-export="hide"` leaves the button out of them. Add a thin `Export.svelte` component with natural height when content grows longer than the window or should become a different artifact. It reads the same saved state and renders without the editor. See [icons and exports](/docs/guides/icons-and-exports/) for native rendering support and browser fallbacks.

`Icon.svelte` draws the Finder icon:

```svelte title="Icon.svelte"
<script lang="ts">
  import doc from "./schema";
</script>
<strong class="counter-icon">{doc.current.count}</strong>
```

Give it ordinary CSS, using the starter's declared tokens:

```css title="styles.css"
* { box-sizing: border-box; }
body { background: var(--slop-surface); color: var(--slop-ink); font-family: system-ui; }
.counter { padding: 2rem; text-align: center; }
.counter-title { font-size: 1.4rem; font-weight: 600; }
.counter-value { font-size: 4rem; font-variant-numeric: tabular-nums; }
.counter button { padding: .8rem 1.2rem; background: var(--slop-accent); color: white; border: 0; border-radius: .5rem; }
.counter button:focus-visible { outline: 3px solid var(--slop-ink); outline-offset: 3px; }
.counter-icon { font-size: 180px; color: var(--slop-accent); }
```

## Build, register, and test persistence

```sh
bun run check
bun run build
bun run register
```

Expected responses, respectively (tool progress omitted; paths vary):

```text
svelte-check found 0 errors and 0 warnings
/Users/you/tiny-counter/dist/tiny-counter.slop
/Users/you/.hitslop/templates/tiny-counter.slop
```

Build without artwork also reports that no artwork was captured. Register captures it.

Build emits `dist/tiny-counter.slop`. Register renders its Finder artwork with the Mac app and installs an immutable template in `~/.hitslop/templates`. In the Mac app, choose **Templates**, select your app, and **Create** a writable copy.

Edit that copy, close immediately after typing, reopen, duplicate it, and export PNG/PDF. Check keyboard focus and a narrower window. Read [styling](/docs/guides/styling/), [data and schemas](/docs/guides/data-and-schemas/), and [icons and exports](/docs/guides/icons-and-exports/) before expanding the app.


## Discover and run your action

Save the writable copy as `My Counter.slop`. From the directory containing it:

```sh
bunx hitslop describe "My Counter.slop"
```

Response excerpt:

```text
Commands (slop call PATH NAME --args JSON)
  Arguments accept only the listed fields.

  countOne — Count one more.
    No arguments. Pass --args '{}'.
```

`describe` also includes the fields, operations, version and current values.

```sh
bunx hitslop call "My Counter.slop" countOne
```

```json
{"result":null,"ids":[]}
```

This action returns no value and inserts no rows, but it increments the saved counter.
If you started at zero, read it back:

```sh
bunx hitslop get "My Counter.slop"
```

```json
{"count":1,"title":"Tiny Counter"}
```

You can also edit the counter directly:

```sh
bunx hitslop apply "My Counter.slop" --op '{"type":"increment","path":["count"],"by":1}'
```

```json
{"ids":[]}
```

The window now shows **2**. A named action lets an agent reuse your app’s behavior;
`apply` and `batch` are available for direct field edits. **Edit ▸ Undo** can undo
agent edits. See the [Checklist walkthrough](/docs/guides/edit-installed-data/)
for commands with arguments and stable row IDs.

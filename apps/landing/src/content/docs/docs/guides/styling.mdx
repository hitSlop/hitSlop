Give the app one clear visual identity: paper for an invoice or note, an instrument for a timer or mixer, or a custom skin when the silhouette helps its job. Keep the primary action obvious at the initial window size. Build depth from a backing surface and purposeful controls rather than repeated generic cards.

## Define public theme tokens

Root `theme.ts` is the source for owner-adjustable colors, fonts, and other visual values:

```ts title="theme.ts"
import { defineTheme } from "@hitslop/document/theme";
export default defineTheme({
  surface: "#f7f4eb",
  panel: "#e3e9df",
  ink: "#182126",
  muted: "#687276",
  accent: "#db6648",
  rule: "color-mix(in srgb, var(--slop-ink) 15%, transparent)",
  font: '"Avenir Next", Avenir, sans-serif',
});
```

The builder writes immutable defaults to `assets/theme.json`; the runtime applies them and owner overrides before mounting the app. Each key becomes `--slop-KEY`, preserving case. `theme.vars` still provides typed references when needed in TypeScript. Do not maintain a second defaults stylesheet.

## Write ordinary CSS

For a Svelte app, the builder includes `styles.css` automatically and emits a separate, minified `assets/app.css`. A custom `main.ts` must import its styles explicitly. Styles ship as ordinary CSS.

```css title="styles.css"
body { color: var(--slop-ink); background: var(--slop-surface); font-family: var(--slop-font); }
.my-slop-paper { padding: clamp(1rem, 5vw, 2.5rem); }
.my-slop-footer {
  border-top: 1px dashed var(--slop-rule);
  background: var(--slop-panel);
  & > span { font-size: 12px; color: var(--slop-muted); }
  & button { border: 2px solid var(--slop-ink); background: var(--slop-accent); }
}
@media (max-width: 360px) { .my-slop-paper { padding: 1rem; } }
```

Use readable app-prefixed classes in markup. Group descendants and interaction states with their base component. Nesting is supported and lowered for the host's Safari target. Use flex/grid reflow, container queries, visible focus, and reduced-motion styles. Keep controls clear of transparent edges.

Bits UI menus can render in portals. Give the portal content its own class and target attributes directly, such as `.my-slop-menu [data-highlighted]`; a selector below the editor root cannot reach a portal outside that root. Svelte `<style>` blocks remain available for component-local rules, but plain CSS is the starter convention.

## Let owners override tokens

Inspect the public contract and current effective theme:

```sh
bunx @hitslop/cli theme get My.slop
bunx @hitslop/cli theme set My.slop --values '{"accent":"#7050ad","surface":"#f5efff"}'
bunx @hitslop/cli theme reset My.slop --token accent
bunx @hitslop/cli theme reset My.slop
```

Themes are files inside the `.slop` package:

| File | Purpose |
| --- | --- |
| `assets/theme.json` | Immutable defaults generated from the author's `theme.ts`. |
| `state/theme.json` | Optional saved overrides for this writable document. |
| `state/document.sqlite` | Loro document data; theme overrides are stored separately. |

For example, the override file can contain:

```json title="state/theme.json"
{"accent":"#7050ad","surface":"#f5efff"}
```

Only tokens declared by the author may be overridden. Use `theme get` to inspect them first. The Mac app currently has no built-in theme picker: use these CLI commands or ask an agent to run them. The website palette picker is an interactive illustration of customization.

Overrides live in `state/theme.json` in a writable document. Use the CLI or an agent rather than editing that file while the document is open. Direct file edits are not watched. The live host applies accepted CLI changes after saving; unknown tokens and invalid values are rejected. Layout selectors stay authored and cannot be overridden. Registered masters and generated templates remain unchanged.

## Design the window and its captures

Every presentation mode receives host page resets, window sizing, and initial size variables. Wrap the interface in `<Slop>` and prefer `height: 100%`, grid, or flex inside it; override the page sizing deliberately only when your layout needs it. Keep surface styling in your app. Transparent and PNG-skinned modes also override ordinary `html`/`body` backgrounds with transparency, so paint the visible surface inside the wrapper. Use the native toolbar handle for dragging. See [manifest and windows](/docs/guides/manifest-and-windows/) and [PNG window skins](/docs/guides/png-window-skins/).

Dedicated `icon` and `exportView` snippets use the same current document and theme as the editor. Export layouts should use normal flow, without nested scrolling or fixed viewport heights. Without an `exportView`, mark editor-only elements `data-slop-export="hide"`. See [icons and exports](/docs/guides/icons-and-exports/) for capture sizing and behavior.

See [package anatomy](/docs/concepts/how-slop-files-work/) for how theme files travel with a document.

---
title: PNG window skins
description: Give a fixed-size slop a custom native silhouette and click-through transparent areas.
---

Start with a built-in `rounded`, `ellipse`, or `capsule` shape and
`background: "transparent"`. Use a PNG when you need a hole in the window or an
outline those shapes cannot describe. PNG skins are fixed-size and cannot resize.
A washer with a transparent center is a useful first test.

## Create the mask asset

Add an RGBA PNG under `assets/`. Its pixel dimensions must exactly match the
manifest window. Alpha defines both the native backing and where the window
accepts pointer input.

```json title="manifest.json"
{
  "$schema": "https://api.hitslop.com/schemas/v1/manifest.schema.json",
  "author": { "name": "Your Name" },
  "slug": "pocket-dial",
  "title": "Pocket Dial",
  "description": "A compact desktop dial.",
  "categories": ["utilities"],
  "presentation": {
    "width": 480,
    "height": 480,
    "skin": "assets/window-mask.png"
  }
}
```

A skinned presentation contains only `width`, `height`, and `skin`. It cannot
also specify `shape`, `background`, or `resizable`, and the native window stays
at the skin's fixed size.

## Align the WebView to the skin

The host draws the PNG behind the page, supplies window sizing, and overrides
ordinary `html`/`body` backgrounds with transparency. Avoid overriding that
transparency with more-specific or `!important` page backgrounds. Wrap the app in `<Slop>`
or mark a framework-neutral root with `data-hitslop-root`; its mount ancestors
fill the window too. No sizing/transparency reset or duplicated pixel constants
are needed; use `100%` or `--slop-width`/`--slop-height`. Align controls with opaque areas of the PNG using ordinary CSS.

The native host exposes initial dimensions as `--slop-width` and `--slop-height`, and
sets `data-slop-presentation="skin"`. These layout rules are disabled for capture.

Pixels below 10% alpha are click-through. Feathered edge pixels may still
receive or reject clicks depending on their alpha, so keep important controls
well inside opaque regions. Transparent holes can intentionally expose and
click the content behind the window.

## Test the physical behavior

- Confirm the PNG is RGBA and exactly matches the manifest dimensions.
- Test clicks around curved edges, transparent holes, and soft shadows.
- Move the window with its native toolbar handle; guest controls do not drag it.
- Check that focus rings and menus stay inside the usable silhouette.
- Preview at native size; a skin is not a responsive window treatment.

The PNG belongs to immutable `assets/`; the native mask is defined by the template.
Document data stays in host-managed state. Media import is deferred.

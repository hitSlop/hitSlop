title: Edit installed documents
description: Discover app actions, call them from the CLI, edit fields, and see each response.
---

Work on the same document as the person using the app. Named commands run the app’s
authored actions; `apply` and `batch` edit fields directly. Both go through the Rust
owner, save accepted edits, and update an open window. **Edit ▸ Undo** includes agent edits.

This walkthrough uses the bundled **Quick Checklist**, with Bun and the Mac app installed.
Run `bunx hitslop` as below, or install globally and use `slop`. Responses show example
paths, versions and shortened row IDs; use the values your own CLI prints. JSON is
compacted in a few places for readability.

## 1. Create and open your own copy

Templates are immutable. Create a writable document at a new path:

```sh
bunx hitslop create --from quick-checklist --output Today.slop
```

```text
/Users/you/Documents/Today.slop
```

```sh
bunx hitslop open Today.slop
```

```text
/Users/you/Documents/Today.slop
```

Keep this terminal in the directory containing `Today.slop`, or use its full quoted path.
Opening the window needs the Mac app; reading and editing a file also work on Linux.

## 3. Run the app’s addTask action

```sh
bunx hitslop call Today.slop addTask --args '{"text":"Book train"}'
```

```json
{"result":{"id":"train"},"ids":["train"]}
```

The real ID will differ. The command returns its result and any inserted IDs. Its
argument validation and behavior are the same as the app’s action; a refusal applies
nothing. A successful call is one atomic edit and one undo step.

Read the document to see the new task alongside the starter tasks:

```sh
bunx hitslop get Today.slop
```

## 4. Edit a field directly

Replace `train` with the `$id` returned above. Row IDs stay stable even if a list is reordered.

```sh
bunx hitslop apply Today.slop --op '{"type":"set","path":["tasks",{"id":"train"},"done"],"value":true}'
```

```json
{"ids":[]}
```

The box checks itself in the open window. An empty `ids` list means no rows were inserted;
it does not mean no edit happened. You can also apply several operations atomically:

```sh
bunx hitslop batch Today.slop --ops '[{"type":"set","path":["tasks",{"id":"train"},"done"],"value":false},{"type":"set","path":["tasks",{"id":"train"},"archived"],"value":false}]'
```

```json
{"ids":[]}
```

This restores the task to unfinished and unfiled. If one operation is invalid, none apply.

## 5. Check the result

```sh
bunx hitslop get Today.slop
```

Response excerpt (the other tasks and title are still present):

```json
{"$id":"train","archived":false,"done":false,"text":"Book train"}
```

Check `get` before retrying after an uncertain outcome, especially an insertion.
Errors go to stderr with a nonzero exit status. For example, an empty task is refused:

```sh
bunx hitslop call Today.slop addTask --args '{"text":""}'
```

```text
Error: Enter a task. (refused)
Not applied.
```

The CLI routes to the open document’s owner or edits a closed document without loading
its interface. It never bypasses a busy writer. There is no editable `data.json` file;
`get` is a read-only snapshot, and templates’ initial values do not change saved work.

For text rewrites based on a read, use `get --snapshot` and pass its `version` with
`apply --base` or `batch --base` so the edit merges with typing since that read.

The editor, Finder artwork, and exported document should feel like the same object. They can have different layouts while reading the same saved data and theme.

## Declare capture views

Use `App.svelte` for the editor, required root `Preview.svelte` and `Icon.svelte`, plus optional `Export.svelte` for captures. The CLI discovers these exact filenames. Preview supplies a compact overview; Export includes the complete document. Without `Export.svelte`, PNG/PDF share/save actions are hidden and CLI export is refused.

```svelte
<main class="note-editor">
  <input aria-label="Title" use:bindText={doc.fields.title} />
  <button onclick={addItem}>Add item</button>
</main>
```

Captures render saved state independently of the editor, with transient state at its defaults. A dedicated export owns its static layout. For content that grows, such as a list or notes, use a thin export component with natural height and derive its content from saved state. Capture views must be synchronous and independent of browser APIs. Dedicated captures ignore the window silhouette; Quick Look displays the saved artwork. An optional export component (`Export.svelte`):

```svelte
<script lang="ts">
  import doc from "./schema";
</script>
<article class="note-export">
  <h1>{doc.current.title}</h1>
  <ul>{#each doc.current.tasks as task (task.$id)}<li>{task.text}</li>{/each}</ul>
</article>
```

Required `Preview.svelte` can show a bounded selection and an honest total:

```svelte
<script lang="ts">
  import doc from "./schema";
</script>
<article class="note-preview">
  <h1>{doc.current.title}</h1>
  <p>{doc.current.tasks.length} tasks</p>
  <ul>{#each doc.current.tasks.slice(0, 5) as task (task.$id)}<li>{task.text}</li>{/each}</ul>
</article>
```

Share components between Preview and Export where useful. Avoid generating a long document just to crop its top for the preview.

`Icon.svelte`:

```svelte
<script lang="ts">
  import doc from "./schema";
</script>
<div class="note-icon">{doc.current.tasks.length}</div>
```

Use the app's existing document facade in capture components. Captures render saved
data in an independent read-only renderer. If an export should show a selected tab or report, save
that choice in the document; transient editor state is not carried into the capture.
An export or icon component that throws fails that capture without changing the live
editor. A later attempt gets a fresh renderer.

Icons, previews, widgets, PNG and selectable vector PDF exports use synchronous Svelte
rendering and Takumi in a restricted Rust process. Use `doc.current`, ordinary flexbox, numeric grid
placement, explicit font properties, and SVG attributes/currentColor. Container
queries, named grid areas and page CSS inside inline SVG are unsupported; ignored
CSS can change the result, so review native captures. Browser-dependent capture
components fail the build with a role/source diagnostic. Use static representations
for canvas, animation or WebGL content. A rendering failure retains previous artwork;
there is no automatic fallback or public renderer override.

Use synchronous `attachments.url(id)` for referenced PNG/JPEG/GIF/WebP images in saved
data. Capture currently loads the whole saved image inventory, capped at 24 MiB,
including images that this role does not display. Blob reads,
imports, remote loading and document writes are unavailable. Missing or unsupported
images fail capture. PNG and PDF share the same native layout, fonts and resources.

Default sans, serif, monospace, Apple color emoji and text-symbol fonts are bundled.
Package additional fonts with `@font-face` and imported `url()` resources; system-font
discovery and remote font loading are unavailable. Fonts need glyph coverage for the
languages your document uses; vector PDF reports uncovered characters as an error.
Do not use Svelte's `css="injected"`; the build collects
the capture component's styles and global CSS.

## Design a macOS widget

Quick Checklist, Water Tracker, Grocery List, Reading Tracker, Habit Heatmap,
Daily Planner, Assignment Tracker and Countdown Milestones include small, medium
and large widget views. Habit Heatmap, Assignment Tracker and Countdown request
approximate 30-minute refreshes for date-dependent content. Daily Planner shows
the date saved in its plan; Water Tracker shows the saved intake log and does not
reset it at midnight. The other views refresh with saved edits.

Add an optional root `Widget.svelte` to compose the same saved document for the desktop:

```svelte
<script lang="ts">
  import type { WidgetProps } from "hitslop/svelte";
  import doc from "./schema";
  let { family, width, height }: WidgetProps = $props();
</script>

<main style:width={`${width}px`} style:height={`${height}px`}>
  <h1>{doc.current.title}</h1>
  {#if family !== "small"}<p>A little more detail.</p>{/if}
</main>
```

Families are `small`, `medium` and `large`. Fit the provided canvas using ordinary CSS;
reuse components, imported assets and theme colors. The host captures a fixed canvas
at 2× through the native renderer. Only the widget component renders. WidgetKit clips its outer
corners; avoid adding an outer shadow or padding just to simulate the system frame.

Create a document from the rebuilt template and open it in hitSlop to generate
its widget images. Add a hitSlop widget from macOS's widget gallery and choose the
document under **Edit Widget → Document**. Only documents containing `Widget.svelte` with a
successful capture appear. Existing documents retain their embedded app, so rebuilding
a template does not add widget support to them. Clicking the image opens that document.

### Keep desktop widgets in full color

If a widget looks gray or loses its colors when you switch to an app, macOS may be
dimming it after capture. Go to **System Settings → Desktop & Dock → Widgets → Dim
widgets on desktop → Never** to keep widgets in full color. **Automatically** switches
between monochrome and full color. On older macOS versions, choose **Widget style →
Full-color** instead. This is a system-wide setting; it doesn't change the captured
image or the document's theme. See [Apple's widget settings](https://support.apple.com/guide/mac-help/add-and-customize-widgets-mchl52be5da5/mac).

### Preview and refresh

In `slop dev`, use the Preview selector to switch between the editor and each widget
family. Accepted edits survive switching, and component/CSS changes update the preview
live. Widget canvases clip overflow; the preview warns when content extends beyond
its canvas.

Successful saves refresh images after a one-second debounce, including edits while
the editor stays open. The running app watches cached documents for closed-document
edits, and catches missed changes at startup or reopen. Updating the renderer or
its bundled fonts also refreshes unchanged cached documents. A failed capture retains
the previous images. The browser preview uses a different renderer; inspect native
images before relying on its appearance.

To request occasional recaptures while hitSlop is running, add
`widget: { refreshMinutes: 30 }` to `slop.ts`. Whole-minute intervals from
15 to 1440 are accepted and require `Widget.svelte`. Only documents used by placed
widgets are scheduled. This requests capture attempts, not an exact visible refresh
rate: macOS controls scheduling and WidgetKit controls display updates. Quitting
hitSlop leaves the last images on the desktop. iOS background capture is not implemented.

## Design an icon at 512 × 512

The native icon canvas is 512 × 512, and the host centers the artwork in it. Give the design breathing room; for example, a tile around 456 pixels wide. Prefer a recognizable silhouette and a few strong marks over tiny text or a screenshot of every control. The icon may summarize current content. Use the same theme colors as the editor, so a person's palette carries into the icon.

The artwork can be rectangular or another shape; only the canvas must be square. Size the artwork to fit within the canvas, including its shadows. For example, a square tile can use:

```css
.note-icon {
  width: 456px;
  height: 456px;
  display: grid;
  place-items: center;
  background: var(--slop-accent);
}
```

`Icon.svelte` is required when authoring. If `Icon.svelte` throws, capture fails rather than silently hiding the broken view.

## Make exports readable

Give export content natural height and normal document flow. Remove selection handles, menus, empty inputs, hover controls, and scroll containers. The optional `Export.svelte` supplies this complete static view; the editor is never captured. Dedicated exports and icons ignore the window's shape mask.

The host sets `html[data-slop-capture="static"]` during capture. Use it for deliberate static layout adjustments:

```css
html[data-slop-capture="static"] .note-export {
  height: auto;
  overflow: visible;
}
```

## Export from the host or CLI

Use the native hover toolbar, File menu, or:

```sh
bunx hitslop export My.slop --format png --output My.png
bunx hitslop export My.slop --format pdf --output My.pdf
```

Successful responses, respectively (your paths will differ):

```text
/Users/you/Documents/My.png
/Users/you/Documents/My.pdf
```

An export never replaces the document it renders. For an open document, hitSlop sends unsent text, saves and copies the document before rendering that copy independently. Closed documents also render from saved state. Both use default local UI state and the saved theme. The open editor is not used as the rendering workspace.

The editor barrier lasts through saving and copying; rendering then proceeds independently. Native capture loads packaged fonts and saved image resources in the restricted child. The live editor's focus, selection and scroll remain unchanged. PNG renders at 2×, up to 16,384 pixels per side and 24 megapixels. PDF export is experimental. It keeps searchable text and vectors on one continuous page, scaled to at most 14,400 points per side; complex layouts and long documents may need further refinement.

Completed captures publish atomically before their deadline. If the acknowledgement is lost, inspect the destination before retrying.

## Quick Look and Finder artwork

Registration, or `slop build --artwork native`, captures `Preview.svelte` and `Icon.svelte` as the initial preview and icon into the template; files you put in `artwork/preview.png` and `artwork/icon.png` are used instead (see [Finder artwork](/docs/guides/build-and-share/#finder-artwork)). Closing a writable document refreshes both images from its saved contents and theme and stores them in the document. Quick Look shows the preview when you press Space, and Finder, Mail and the share sheet show the icon, including on a Mac that received the file. A document without artwork shows hitSlop's document icon. Recents follows the document too. Templates keep their initial artwork. Failed captures retain the previous images. Artwork is a derived preview, not document state.

Test normal and narrow windows, empty and populated data, themed output, default local views, saved view choices, and exports from open and closed documents. Check both PNG and PDF; a good editor screenshot alone does not prove a good exported layout.

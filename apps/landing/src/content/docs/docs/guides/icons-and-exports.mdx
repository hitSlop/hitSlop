title: Icons, previews, and exports
description: Design live icons and export views, then capture native PNG and PDF output.
---

The editor, Finder artwork, and exported document should feel like the same object. They can have different layouts while reading the same saved data and theme.

## Declare capture views

Use `App.svelte` for the editor and optional root `Export.svelte` and `Icon.svelte` for captures. The CLI discovers these exact filenames. Export receives `mode: "preview" | "export"`:

```svelte
<main class="note-editor">
  <input aria-label="Title" use:bindText={doc.fields.title} />
  <button onclick={addItem}>Add item</button>
</main>
```

Captures render saved state in a fresh page, with transient state at its defaults. A dedicated export mounts without the editor and owns its static layout. For content that grows, such as a list or notes, use a thin export component with natural height and derive its content from saved state. Without `Export.svelte`, preview and export mount `App.svelte`; mark composers, menus and tabs with `data-slop-export="hide"` and make any scrolling layout adjustments in your CSS. The default Quick Look preview is a 2× snapshot of the window that preserves its silhouette. An export component (`Export.svelte`):

```svelte
<script lang="ts">
  import doc from "./schema";
</script>
<article class="note-export">
  <h1>{doc.current.title}</h1>
  <ul>{#each doc.current.tasks as task (task.$id)}<li>{task.text}</li>{/each}</ul>
</article>
```

`Icon.svelte`:

```svelte
<script lang="ts">
  import doc from "./schema";
</script>
<div class="note-icon">{doc.current.tasks.length}</div>
```

Use the app's existing document facade in capture components. Captures render saved
data in a fresh read-only page. If an export should show a selected tab or report, save
that choice in the document; transient editor state is not carried into the capture.
Without `Export.svelte`, a fresh rendering of `App.svelte` with its default local state is the fallback.
An export or icon component that throws fails that capture without changing the live
editor. A later attempt gets a fresh rendering page.

## Design a macOS widget

Add an optional root `Widget.svelte` to compose the same saved document for the desktop:

```svelte
<script lang="ts">
  import type { WidgetProps } from "hitslop/svelte";
  import doc from "./schema";
  let { family, width, height }: WidgetProps = $props();
</script>

<main style:width={`${width}px`} style:height={`${height}px`}>
  <h1>{doc.current.title}</h1>
  {#if family !== "small"}<p>A little more detail.</p>{/if}
</main>
```

Families are `small`, `medium` and `large`. Fit the provided canvas using ordinary CSS;
reuse components, imported assets and theme colors. The host captures a fixed canvas
at 2× in a fresh read-only page. Only the widget view mounts. WidgetKit clips its outer
corners; avoid adding an outer shadow or padding just to simulate the system frame.

Create a document from the rebuilt template, open it in hitSlop, then close it to publish
its widget images. Add a hitSlop widget from macOS's widget gallery and choose the
document under **Edit Widget → Slop**. Only documents containing `Widget.svelte` with a
successful capture appear. Existing documents retain their embedded app, so rebuilding
a template does not add widget support to them. Clicking the image opens that document.

By default, images refresh on close. To request occasional recaptures while hitSlop is
running, add `widget: { refreshMinutes: 30 }` to `slop.ts`. Whole-minute intervals from
15 to 1440 are accepted and require `Widget.svelte`. Only documents used by placed
widgets are scheduled. This requests capture attempts, not an exact visible refresh
rate: macOS controls scheduling and WidgetKit controls display updates. Quitting
hitSlop leaves the last images on the desktop. iOS background capture is not implemented.

## Design an icon at 512 × 512

The native icon canvas is 512 × 512, and the host centers the artwork in it. Give the design breathing room; for example, a tile around 456 pixels wide. Prefer a recognizable silhouette and a few strong marks over tiny text or a screenshot of every control. The icon may summarize current content. Use the same theme colors as the editor, so a person's palette carries into the icon.

The artwork can be rectangular or another shape; only the canvas must be square. Size the artwork to fit within the canvas, including its shadows. For example, a square tile can use:

```css
.note-icon {
  width: 456px;
  height: 456px;
  display: grid;
  place-items: center;
  background: var(--slop-accent);
}
```

An absent icon is optional. If `Icon.svelte` throws, capture fails rather than silently hiding the broken view.

## Make exports readable

Give export content natural height and normal document flow. Remove selection handles, menus, empty inputs, hover controls, and scroll containers. With `Export.svelte`, the editor is never captured. Without it, a fresh `App.svelte` rendering saved data is the fallback: mark editing-only elements with `data-slop-export="hide"`, and native text inputs render as wrapping text. Dedicated exports and icons ignore the window's shape mask.

The host sets `html[data-slop-capture="static"]` during capture. Use it for deliberate static layout adjustments:

```css
html[data-slop-capture="static"] .note-export {
  height: auto;
  overflow: visible;
}
```

## Export from the host or CLI

Use the native hover toolbar, File menu, or:

```sh
bunx hitslop export My.slop --format png --output My.png
bunx hitslop export My.slop --format pdf --output My.pdf
```

Successful responses, respectively (your paths will differ):

```text
/Users/you/Documents/My.png
/Users/you/Documents/My.pdf
```

An export never replaces the document it renders. For an open document, hitSlop sends unsent text, saves and copies the document before rendering that copy in a fresh page. Closed documents also render from saved state. Both use default local UI state and the saved theme. The open editor is not used as the rendering workspace.

The editor barrier lasts through saving and copying; rendering then proceeds independently. Capture waits for fonts, visible images and a stable layout in the fresh page. The live editor's focus, selection and scroll remain unchanged. PNG renders at 2×, up to 16,384 pixels per side and 24 megapixels. PDF keeps searchable text and vectors on one continuous page, scaled to at most 14,400 points per side.

Completed captures publish atomically before their deadline. If the acknowledgement is lost, inspect the destination before retrying.

## Quick Look and Finder artwork

Registration, or `slop build --artwork native`, captures the initial preview and, when declared, icon into the template; files you put in `artwork/preview.png` and `artwork/icon.png` are used instead (see [Finder artwork](/docs/guides/build-and-share/#finder-artwork)). Closing a writable document refreshes both images from its saved contents and theme and stores them in the document. Quick Look shows the preview when you press Space, and Finder, Mail and the share sheet show the icon, including on a Mac that received the file. A document without artwork shows hitSlop's document icon. Recents follows the document too. Templates keep their initial artwork. Failed captures retain the previous images. Artwork is a derived preview, not document state.

Test normal and narrow windows, empty and populated data, themed output, default local views, saved view choices, and exports from open and closed documents. Check both PNG and PDF; a good editor screenshot alone does not prove a good exported layout.


In `slop dev`, use the Preview selector to switch between the editor and each widget family.
Accepted edits survive switching, and component/CSS changes update the preview live. Widget
canvases clip overflow; the preview warns when the target extends beyond its canvas.

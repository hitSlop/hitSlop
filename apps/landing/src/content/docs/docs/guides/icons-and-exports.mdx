---
title: Icons, previews, and exports
description: Design live icons and export views, then capture native PNG and PDF output.
---

The editor, Finder artwork, and exported document should feel like the same object. They can have different layouts while reading the same live state and theme.

## Declare capture views

`<Slop>` accepts optional `icon` and `exportView` snippets:

```svelte
<Slop>
  <main class="note-editor">
    <input aria-label="Title" use:bindText={doc.fields.title} />
    <button onclick={addItem}>Add item</button>
  </main>
  {#snippet icon()}
    <div class="note-icon">{doc.current.tasks.length}</div>
  {/snippet}
  {#snippet exportView()}
    <article class="note-export">
      <h1>{doc.current.title}</h1>
      <ul>{#each doc.current.tasks as task (task.$id)}<li>{task.text}</li>{/each}</ul>
    </article>
  {/snippet}
</Slop>
```

Use your app's existing document facade; never open a second store for capture. Snippets mount lazily, so they should derive content from current state, not keep a private copy of it. A rendering failure in an export or icon snippet rejects that capture without replacing the editor or reporting an application-render error. Capture restores the editor and clears the snippet's failure state; a later attempt renders it again. Editor rendering failures still use the native application-error recovery path.

## Design an icon at 512 × 512

The native icon canvas is 512 × 512, and `<Slop>` centers the snippet in it. Give the design breathing room; for example, a tile around 456 pixels wide. Prefer a recognizable silhouette and a few strong marks over tiny text or a screenshot of every control. The icon may summarize current content. Keep its theme tokens aligned with the editor.

The artwork can be rectangular or another shape; only the canvas must be square. Size the artwork to fit within the canvas, including its shadows. For example, a square tile can use:

```css
.note-icon {
  width: 456px;
  height: 456px;
  display: grid;
  place-items: center;
  background: var(--slop-accent);
}
```

An absent icon is optional. If you declare an icon and it throws, capture fails rather than silently hiding the broken view.

## Make exports readable

Give export content natural height and normal document flow. Remove selection handles, menus, empty inputs, hover controls, and scroll containers. If no dedicated export view is declared, the editor is the fallback; mark editing-only elements with `data-slop-export="hide"`.

The host sets `html[data-slop-capture="static"]` during capture. Use it for deliberate static layout adjustments:

```css
html[data-slop-capture="static"] .note-export {
  height: auto;
  overflow: visible;
}
```

## Export from the host or CLI

Use the native hover toolbar, File menu, or:

```sh
bunx @hitslop/cli export My.slop --format png --output My.png
bunx @hitslop/cli export My.slop --format pdf --output My.pdf
```

The destination must be outside the package. Open documents export the selected live view after sending unsent text and saving. Closed documents render a private saved snapshot using their initial view. Theme overrides apply in both cases. The original document is not used as a scratch rendering workspace.

Completed captures publish atomically before their deadline. If the acknowledgement is lost, inspect the destination before retrying.

## QuickLook and Finder artwork

Native build/registration captures initial artwork into `QuickLook/Preview.png` and, when declared, `QuickLook/Icon.png`. Writable documents refresh artwork through the host's saved-document capture flow. Artwork is a derived preview, not document state.

Test normal and narrow windows, empty and populated data, themed output, live selected views, and closed exports. Check both PNG and PDF; a good editor screenshot alone does not prove a good exported layout.

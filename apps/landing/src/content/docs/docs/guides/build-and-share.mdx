---
title: Build, register, and share
description: Turn source into an immutable template, create writable copies, and distribute useful output.
---

Keep three objects distinct: the source project you edit, the runtime template you build, and the writable document someone creates from that template.

## Check and build

In a generated project:

```sh
bun run check
bun run build
```

Build validates the manifest and initial values, compiles Svelte and plain CSS, emits the schema and theme defaults, and uses the installed Mac app to capture native artwork. Output goes to `dist/SLUG.slop`. It contains no source, dependencies, caches, or personal document state. A failed build must not replace an existing successful output, and a build must never overwrite a writable document.

Native capture uses the installed hitSlop app; authoring never compiles Swift or installs another document engine.

## Register a local template

```sh
bun run register
```

Registration builds and installs an immutable master in `~/.hitslop/templates`. The Mac catalog lists it alongside built-in starters. Choose **Create** and save a separate writable document. Re-registering backs up the previous master outside the catalog, then replaces it; it does not modify documents already created from it.

For terminal document creation, see [create and open a writable document](/docs/guides/cli-workflows/#create-and-open-a-writable-document).

## Share a template or a document

For a reusable app, distribute the freshly built `.slop` template. A `.slop` is a directory package; zip it when transferring through a service that does not preserve directory bundles. The recipient needs the hitSlop app. Unpack the download first, then place the complete `.slop` template in `~/.hitslop/templates`. Refresh the Mac catalog and choose **Create** to make a writable copy.

For a filled document, save and close it before copying or zipping the complete package. Its `state/` contains the actual private document and theme overrides. Inspect that content before sharing a writable copy; distributing source or a clean template does not include it. Keep active documents outside synced folders.

For read-only output, export PNG or PDF:

```sh
bunx @hitslop/cli export My.slop --format pdf --output My.pdf
```

See [icons and exports](/docs/guides/icons-and-exports/) for layouts and live-versus-closed capture behavior. Live collaboration is [coming soon](/docs/guides/live-sharing/). Public template publishing and hosted discovery remain future work; file distribution and image/PDF exports work locally today.

## Release your source

Include the manifest, schema, initial values, theme, stylesheet, components, package manifest, and Bun lockfile. Keep generated `dist/`, writable documents, and dependencies out of source control. Test a fresh install, the smallest supported window, keyboard interaction, close-after-type, duplicate, theme reset, icon capture, and PNG/PDF output.

title: Build, register, and share
description: Turn source into an immutable template, create writable copies, and distribute useful output.
---

Keep three objects distinct: the source project you edit, the runtime template you build, and the writable document someone creates from that template.

## Check and build

In a generated project:

```sh
bun run check
bun run build
```

Expected responses (tool progress omitted; paths vary):

```text
svelte-check found 0 errors and 0 warnings
/Users/you/my-slop/dist/my-slop.slop
```

`check` runs the project's own `svelte-check` and TypeScript, pinned by the starter; if the checker is missing, the CLI prints an install hint.

Build validates the app declaration and initial values, compiles Svelte and plain CSS, evaluates the schema and theme defaults, and packs everything into one template file, checked the way the Mac app checks it when it opens it. Output goes to `dist/SLUG.slop`. It contains no source, dependencies, caches, or personal document state. A failed build must not replace an existing successful output, and a build must never overwrite a writable document.

Build runs on macOS and Linux and needs only Bun. It refuses a project whose `hitslop` is newer than the CLI supports; update `hitslop` when it says so.

### Finder artwork

A template's Finder preview and icon come from two sources:

- **Your files.** Images you declare as `artwork: { preview, icon }` in `defineSlop` (imported like any asset) are packed into the template on any platform. Use PNGs; the icon is 512 × 512.
- **Rendered for you.** On macOS and Linux, `bun run build` and `bun run register` render whichever of the two you didn't supply from your `Preview.svelte` and `Icon.svelte` views, in the same step that packs the template. This needs only the CLI: no hitSlop app, Swift or Xcode. If a view can't render, the build fails.

## Register a local template

```sh
bun run register
```

Response after a successful build and artwork capture:

```text
/Users/you/.hitslop/templates/my-slop.slop
```

Registration builds and installs an immutable master in `~/.hitslop/templates`. The Mac catalog lists it alongside built-in starters. Choose **Create** and save a separate writable document. Re-registering replaces the previous master once the new build is complete; it does not modify documents already created from it.

For terminal document creation, see [create and open a writable document](/docs/guides/cli-workflows/#create-and-open-a-writable-document).

## When a change doesn't appear

A document contains the app version it was created with. Editing source, rebuilding a
template, or reinstalling hitSlop does not replace the app inside that document. This
also applies to fixes in a library, new capability declarations, and changes to defaults.

For your own project, run `bun run register` and create a **new** document from that
template. A plain `bun run build` updates `dist/SLUG.slop`, not the registered master.
Keep the old document if it contains work you want to preserve; automatic app upgrades
and schema migration are not available.

## Share a template or a document

For a reusable app, distribute the freshly built `.slop` template: it is one file, so it travels by Mail, AirDrop or any file service as it is. The recipient needs the hitSlop app. Opening a template asks where to create a writable document from it; to keep it in the catalog, place it in `~/.hitslop/templates` and refresh.

For a filled document:

1. Open it and choose **Share a Copy…** in its toolbar. hitSlop saves what you typed and prepares a separate copy.
2. Choose a destination in the Mac share sheet.
3. Keep editing your original. The recipient gets an independent document with its attachments and theme overrides.

The copy includes the document’s content; distributing source or a clean template does not. Keep active documents outside synced folders.

For read-only output, export PNG or PDF:

```sh
bunx hitslop export My.slop --format pdf --output My.pdf
```

```text
/Users/you/Documents/My.pdf
```

See [icons and exports](/docs/guides/icons-and-exports/) for layouts and saved-state capture behavior. Live collaboration is [coming soon](/docs/guides/live-sharing/). Public template publishing and hosted discovery remain future work; file distribution and image/PDF exports work locally today.

## Release your source

Include the root role files (`slop.ts`, `schema.ts`, `App.svelte`, `Preview.svelte`, `Icon.svelte`, and any `Export.svelte`, `Widget.svelte` and `commands.ts`), the modules, styles and assets they import, `package.json`, and the Bun lockfile. Keep generated `dist/`, writable documents, and dependencies out of source control. Test a fresh install, the smallest supported window, keyboard interaction, close-after-type, duplicate, theme reset, icon capture, and PNG/PDF output.

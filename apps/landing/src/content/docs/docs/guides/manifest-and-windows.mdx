---
title: Manifest and windows
description: Define a slop's identity, discovery metadata, initial window, and native window behavior.
---

Read `manifest.json` first. It is the package contract for a slop: its identity,
author, catalog metadata, and initial native window. The manifest is immutable in
a built template or document, so make changes in the source project and rebuild.
Writable state is managed by the document runtime; media import is deferred.

## Start with a complete manifest

```json title="manifest.json"
{
  "$schema": "https://api.hitslop.com/schemas/manifest.schema.json",
  "author": {
    "name": "Your Name",
    "url": "https://example.com"
  },
  "slug": "tiny-counter",
  "title": "Tiny Counter",
  "description": "A small counter that stays on your desktop.",
  "categories": ["utilities"],
  "presentation": {
    "width": 420,
    "height": 520,
    "resizable": true,
    "shape": "22px"
  }
}
```

## Identity and discovery fields

| Field | Rule |
| --- | --- |
| `$schema` | Must be `https://api.hitslop.com/schemas/manifest.schema.json`. |
| `author.name` | Required, 1–80 characters with at least one non-space character. This attribution travels with the template. |
| `author.url` | Optional HTTP or HTTPS URL, up to 2,048 characters. |
| `slug` | 2–64 lowercase letters or numbers in kebab case, such as `tiny-counter`. |
| `title` | Required, 1–80 characters. |
| `description` | Required, 1–240 characters. Explain the slop's specific job. |
| `categories` | One or two unique catalog categories. |

Categories are `productivity`, `utilities`, `finance`, `media`, `games`,
`developer-tools`, `education`, `business`, `personal`, `health`, `creative`, `music`,
and `other`.

## Set the initial window

`presentation.width` must be an integer from 240 to 4,096 pixels. Height must
be an integer from 180 to 4,096 pixels. Choose the smallest size at which the
main job feels complete; this becomes the initial native window and the basis
for capture work.

Standard windows support these options:

| Option | Values | Behavior |
| --- | --- | --- |
| `resizable` | `true` or `false` | Whether the user can resize the window. The host defaults to `true`. |
| `shape` | CSS radius string or SVG path object | Defines the native silhouette; defaults to `"22px"`. |
| `lockAspect` | Boolean, default false | Preserves the initial width/height ratio when resizing. |
| `background` | `transparent` | Makes the WebView background transparent for a custom HTML surface. |

## Choose a window shape

`shape` is either a CSS radius string or a vector path. The host builds one native
silhouette from it and uses that silhouette for clipping, click-through, and the
mask on window-sized fallback PNG captures.

**Radius strings** accept one to four nonnegative `px` or `%` values, unitless `0`,
and an optional `/` followed by vertical radii. Corners run top-left, top-right,
bottom-right, bottom-left, and overlapping radii shrink as in CSS. Use `"50%"` for an
ellipse or `"9999px"` for a pill. Radius strings are limited to 256 ASCII characters.

```json
"shape": "48px 8px 72px 0 / 24px 32px 18px 0"
```

**Vector paths** use `{ "path", "viewBox", "fillRule" }`. Coordinates are top-left
and y-down. `viewBox` defaults to the manifest dimensions, so the path scales when
the window resizes, and `fillRule` defaults to `nonzero`. All SVG path commands are
supported. Paths are limited to 4,096 ASCII characters, 512 commands (implicit
repetitions count) and 2,048 expanded segments; each `viewBox` side is 1–16,384. A
concave notch on the right edge:

```json
"shape": {
  "path": "M24 0 H456 Q480 0 480 24 V132 L432 156 L480 180 V336 Q480 360 456 360 H0 V48 Z",
  "viewBox": [480, 360]
}
```

Set `"fillRule": "evenodd"` and add a second subpath to cut a hole. Clicks in the
hole reach whatever is underneath the window:

```json
"shape": {
  "path": "M24 0 H456 Q480 0 480 24 V336 Q480 360 456 360 H0 V48 Z M350 56 a44 32 0 1 0 0 64 a44 32 0 1 0 0 -64 Z",
  "viewBox": [480, 360],
  "fillRule": "evenodd"
}
```

Add `"lockAspect": true` to keep the window at its initial ratio while resizing.
Invalid geometry rejects the manifest. Dedicated exports and icons remain
independent of the window silhouette. Radius shapes expose their radius to the
page as `--slop-window-radius`; path shapes set it to `0`.

The window is the stage in every mode. The host resets the page margins, and
the automatic app root (or a framework-neutral `data-hitslop-root` element) and its mount
ancestors fill the window. Prefer `height: 100%`, grid, or flex inside it rather
than repeating page sizing or using `100vh`; deliberate overrides remain possible.
For a transparent window, draw the visible surface inside your app: the host
overrides ordinary `html`/`body` backgrounds with transparency, and a more specific or
`!important` page background defeats it.

The native host exposes the presentation to your CSS:

| Host value | Meaning |
| --- | --- |
| `data-slop-presentation` | `standard`, `transparent`, or `skin` |
| `--slop-window-radius` | The radius shape; `0` for paths, absent for PNG skins |
| `data-slop-resizable` | Present when the person can resize the window |
| `--slop-window-width`, `--slop-window-height` | Initial dimensions, not live viewport measurements |
| `data-slop-controls` | `visible` or `hidden`, following the native hover toolbar |

`slop dev` previews the window at its manifest size with the same shape or skin, but
without these host values; lay out from the actual viewport rather than assuming them.

Keep controls inside the visible shape and test focus, resizing, and dragging
at the smallest size you support.

## Resize the app and move the window

An unskinned app can request a new bounded native size at runtime. The host
keeps the result on the visible screen and returns the applied size; the manifest
remains the next launch's initial size. Browser preview has no native window: resize
it with the preview's handle or arrow keys.

```ts
import { resizeWindow } from "@hitslop/document/svelte";

// Ignored in browser preview, which has no native window.
await resizeWindow({ width: 560, height: 680 });
```

Use the native toolbar handle to move the window. There is no guest window-drag
API; buttons, sliders, and text selection retain their ordinary behavior.

## Show controls on hover

For actions that should appear only on hover, follow `html[data-slop-controls="visible"]`.
The host starts it at `hidden` and updates it with the native toolbar, including the
toolbar's hit testing and its 0.8-second hide delay. Focus, Tab and disabled controls
don't reveal these actions. Hide them with `visibility: hidden` and
`pointer-events: none`, not opacity alone, so they also leave keyboard navigation.

```css
.my-slop-actions { visibility: hidden; pointer-events: none; }
html[data-slop-controls="visible"] .my-slop-actions { visibility: visible; pointer-events: auto; }
/* Browser preview has no attribute; fall back to :hover there only. */
html:not([data-slop-controls]) .my-slop-shell:hover .my-slop-actions { visibility: visible; pointer-events: auto; }
```

Mark these controls `data-slop-export="hide"` too, or leave them out of your export
view.

## Use a PNG skin for a custom silhouette

A skinned presentation contains only `width`, `height`, and `skin`. It is fixed
at that exact size and cannot also use `shape`, `background`, or `resizable`.
See [PNG window skins](/docs/guides/png-window-skins/) for the full asset and
hit-testing workflow.
